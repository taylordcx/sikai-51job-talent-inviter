# 顾问选择与整轮范围

## 开始前的选择

先从当前页面读取真实岗位列表和工作经验下拉选项，再让顾问按实际名称选择，不凭记忆列举年限档位。

1. 招聘岗位：显示搜索页实际可选岗位的完整名称，另提供“全部可选岗位”。顾问可说岗位名称或全部；名称重复时用页面已有的地点等信息区分。不要把页面“不限职位”当作“全部岗位”。若列表因关键词或分页不完整，应说明范围；顾问要求全部在招岗位时，按主流程读取职位管理并验证各岗位可关联后再执行。
1a. **读出岗位列表后不得就此结束回合**：立即用交互选择（如 AskUserQuestion）让顾问直接选下一步动作，而不是停在"等我指示"。选项至少包含：
    - 按某个岗位搜人：把每个岗位（含地点、薪资等摘要）各作为一个选项，另加"全部可选岗位"；
    - 看候选人卡片：用当前选中岗位和页面现有条件先查看结果卡片，看完再决定是否调整条件或邀约。
    顾问也可自行输入其他指令。选完直接进入对应流程，不再追加"是否开始"之类的确认。
1b. **顾问选定岗位（按某个岗位搜人 / 看候选人卡片）后，下一步就是邀约 Hi 聊目标确认**：岗位落定的瞬间立即执行，不得跳过此步直接进入条件筛选。
    1. 立即调用 `cdp_tools.mjs points` 读取当前 Hi 聊余额；
    2. 用 AskUserQuestion 问"此次邀约目标几人"，把余额与精选扣点规则放在问题描述里：
       - 描述："当前 Hi 聊还剩 X 点（精选候选人每次额外扣 1 点、共 2 点）；本次最多邀约 = min(目标, 当前点数) 位非精选，或 floor(当前点数/2) 位精选。"
       - 选项常用档：1 / 3 / 5 / 10（按本轮真实可选人数给，不出现"已选数超余额"这种空话）；
       - 加"先不邀约，只看候选人"作为兜底选项。
    3. 顾问回答后立即记录 `target = K`（默认 K = min(顾问回复, 当前点数)）；不要在等顾问回答前进入条件筛选和搜索。
    4. 后续条件筛选、读卡片、发 Hi 全程按 target 推进。`hi` 子命令 / `invite_batch.mjs` 都接受 `--budget $target`，超出自动停。
2. 工作经验：展示当前下拉支持的实际档位，让顾问选择；明确“不限”则清除旧值。同一对话已提供且能精确对应选项的值无需重问。全部岗位默认共用顾问本次所选档位；顾问给出各岗位不同年限时分别执行。无法精确对应时询问，不能擅自取相近范围。
3. 沿用先前约定：年龄仍由顾问本次填写或明确不限，已有本轮答案不重问；不把历史22—32岁写成永久默认。顾问还未提供的必须信息可与岗位、年限一起简短收集，信息齐全后立即开始，不再加一次“是否开始”确认。

不询问搜索关键词：每次通过岗位下拉选择职位，保留平台自动带出的搜索词。

## 单岗位与全部岗位

单岗位只处理所选岗位。全部岗位按已展示的页面顺序逐个处理，不合并不同岗位的关键词或任职要求。开始时说明岗位顺序以及全局上限，不承诺每个岗位都有邀约名额。

每次切换岗位后重新设置本轮工作经验、年龄及其他筛选，居住地使用约定16省，在页面按10+6两批筛选，期望工作地义乌＋杭州最后设置并读回。先处理该岗位第一批结果，再第二批，再下一个岗位；达到全局停止条件立即结束，不强行跑完所有岗位。

默认整轮最多查看500位不重复候选人，确认成功发起3次Hi后停止；顾问明确指定其他上限则覆盖。两个数字都跨岗位、跨居住地批次累计，不是每岗位500人或每岗位3次。可用点数更少时按实际额度处理，失败点击不算成功，结果不明按原规则停止核实，不能为凑够3人补发。

遇到明确合适的立即邀约，不等看满500人再排序；证书、院校等仍按卡片分析规则处理。跨岗位出现同一候选人只计一次查看人数；已成功、正在处理或发送结果待确认者不再联系。某人不适合前一岗位，不代表不适合后一岗位，可复用已读卡片证据对照当前岗位重新判断；事实不能可靠复用时只读复核。分析记录需区分候选人唯一数与岗位判断次数。

## 节省重复读取与续跑

按页读取可见卡片，一次提取必要信息，先排除明确不符合者，再分析剩余候选人；点击Hi前仍须重新核对该人的身份、按钮与页面状态。只保存简短证据、结论、稳定标识、岗位及批次/页码进度，不保存整页简历或重复输出长分析。只有用户要求继续同一轮时沿用该轮计数和进度；新一轮重新收集当轮条件，同时继续尊重历史已联系记录。
