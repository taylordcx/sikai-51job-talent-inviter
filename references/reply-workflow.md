# 人才回复与追邀（沟通页跟进流程）

本流程处理**已经发出去的邀约的后续跟进**：在沟通页读取会话，找出「我方发了邀约、隔了一天候选人还没回」的会话，再追发一条消息。

与搜索/邀约流程是两条独立路线：搜索邀约是「找新人」，本流程是「跟旧人」。两者共用第 0 步环境闸门和同一套 CDP 工具链。

## 页面实测选择器（2026-10-19，Chrome/155；浏览器改版需重新核对）

- 沟通页：`https://ehire.51job.com/Revision/chat`（工作台 → 人才沟通）。左侧会话列表 + 右侧会话详情。
- 会话项：`.conversation-item`，内容在 `.item-content`——行1=姓名+岗位；时间行匹配
  `刚刚|N分钟前|HH:MM|昨天|MM/DD|MM-DD HH:MM`；「已投」等状态徽章会混进行文本，解析要剥离。
- 消息：**直接遍历内层 `.message-item`**（外层 `.im-message-item` 不可靠，有的消息没外壳）。
  `.mine`=我方；`.im-message-time`=时间分隔（作用于其后消息）；消息文本在 `.chat-bubble`，
  前缀「已读/未读」是状态不是内容，要剥掉并记入 read 字段。
- 消息类型：`.text-element`=文字；`.invite-delivery-element`=系统邀约（"已邀请对方投递…"）；
  `.phone-sms-card`=该人才偏好电话/短信（IM 发不出，转电话）。
- 输入框：`[contenteditable=true].input-textarea_self`（contenteditable，注入用 execCommand insertText，
  不能 `.value=`）；发送按钮 `button.new-send-button`。
- 预览方向判定：`[已读]`/`[未读]` 前缀=我方最后一条文字；`已邀请对方投递`=我方系统邀约；
  `[已同意]`/`对方…`=对方有动作（转顾问）。**消息区判定比列表预览可靠**，预览判不了的回退到点开会话读消息区。

## 边界与红线

- **只跟进顾问自己发出去的会话**，不主动给从未沟通过的人发消息。
- **追发不等于重新邀约**：已经在沟通中的会话，追发一般不再消耗 Hi 聊点数；是否扣点以页面实际提示为准，扣点异常立即停止。
- **不代替顾问做决定**：涉及薪资谈判、面试时间地点确认、录用意向、候选人提出的特殊要求（比如居家办公、薪资上浮），一律不自动回复，标记为「待顾问处理」交回给人。
- 出现验证码、频繁操作提示、访问限制，**立即停止**，优先于任何追发目标。
- 单次运行追发上限默认 **20 条**，顾问可另行指定；不无限刷会话。

## 第 0 步：环境闸门

与 SKILL.md 第 0 步完全一致，先跑 `node scripts/env_check.mjs`。判定为 `CLOUD_SANDBOX` / `UNKNOWN` 时停止，不启动浏览器。

## 追发判定规则（四条同时满足才进待追发名单）

1. 会话里**最后一条消息是我方发出的**（说明球在对方那边）；
2. 该消息发送时间距今 **≥ 24 小时**（顾问说"隔一天"就是这个口径；顾问明确指定 N 天时按 N 天）；
3. 我方发出之后，**候选人没有任何回复**；
4. 同一候选人：**本轮最多追发 1 次**；距上次追发 **< 7 天**的不重复追。

### 不追发的情况（分别归入不同状态）

| 情况 | 状态 | 处理 |
|---|---|---|
| 候选人已回复（无论意向） | 待顾问处理 | 不自动发，把回复原文交给顾问 |
| 明确拒绝 / 说不考虑 | 已终止 | 标记后不再跟进 |
| 距上次追发 < 7 天 | 冷却中 | 本轮跳过 |
| 会话异常 / 账号被限制 | 异常 | 停止并报告 |

## 话术模板（内置，顾问可随时覆盖）

话术按「候选人情况」选一条，不是群发同一句。顾问当轮给了自己的话术时，一律用顾问的。

### T1 · 隔天未回（默认追发话术，温和提醒）

> 您好，我是思凯的招聘顾问。前两天给您发过【岗位名】的信息，不知道您有没有看到？
> 简单说下：base 义乌，薪资 薪资范围，13薪。如果感兴趣回复我一声，我把岗位详情发您。

### T2 · 三天以上未回（带退出口，降低打扰感）

> X先生/女士您好，之前发您的【岗位名】目前还在招。
> 如果您现在不考虑换工作，麻烦回我一句，我就不打扰了；想了解的话我随时可以细聊。

### T3 · 已读不回（提问式切入，比陈述句更容易得到回应）

> 您好，冒昧问一句——您目前是在义乌这边工作，还是有打算来义乌发展？
> 我们这边财税岗位还有坑位，想先看看跟您的情况匹不匹配。

### T4 · 候选人回复了但意向不明

**不自动发。** 归入「待顾问处理」，把候选人原文 + 建议回复方向写进跟进表，等顾问定。

### 话术使用约束

- 岗位名、薪资、地点必须从**当前沟通会话关联的岗位**读取，不能凭记忆填，更不能编。
- 一次只发一条消息，不连发；发完核对一次。
- 不使用"亲""呢""哦"这类过度客套的措辞；不用感叹号堆砌。

## 执行步骤

1. 环境闸门 → 浏览器就绪 → 顾问已登录（登录由顾问手动完成）。
2. 打开沟通页，读取会话列表（候选人、关联岗位、最后消息方向、最后消息时间、是否已回复）。
3. 按上面的四条规则筛选，产出**待追发名单**，先把名单给顾问过目并确认话术（顾问明确授权"直接发"时可跳过这一步）。
4. 逐条发送：打开会话 → 输入话术 → 发送 → 读回消息列表确认这条真的出现在对话里。
5. 失败、被限流、出现验证码 → 立即停止，报告已完成的进度。
6. 产出跟进表。

## 输出：跟进表

跑完生成一份 HTML 跟进表（写入顾问指定的位置，默认工作区），至少包含：

| 字段 | 说明 |
|---|---|
| 候选人 | 称呼/姓名（按页面显示） |
| 关联岗位 | 会话对应的岗位名 |
| 首次邀约时间 | 我方第一条消息的发送时间 |
| 是否回复 | 未回复 / 已回复（附原文摘要） |
| 追发状态 | 已追发 / 冷却中 / 待顾问处理 / 已终止 |
| 使用话术 | T1/T2/T3/顾问自定义，附实际发送文本 |
| 下一步 | 等回复 / 顾问跟进 / 不再跟进 |

汇报口径与跟进表对齐：本轮读取会话数、待追发数、实际追发成功数、待顾问处理数、冷却中数、停止原因。**追发成功不等于对方会回复**。
