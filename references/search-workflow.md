# 搜索条件与刷新核对

本文件用于人才搜索阶段。使用已连接的浏览器工具或 Computer Use，按当次页面文字、标签和控件定位；不用录制坐标重放。录制只证明出现过的控件及操作，不证明所有选择、点击及发送结果都已完整捕获。

## 建立本轮条件清单

- 区分关联招聘岗位、搜索关键词、期望工作地与居住地。切换岗位后重新读取关键词和地点，平台可能自动改变它们；以本轮用户要求为准，不沿用刚被替换的旧值。
- 检查搜索页顶部当前模式。录制出现过“学生”文字，但没有完整的模式切换过程；应读取当前控件及可选项，核对是否符合本轮招募对象，不能仅凭这段文字断言整页只包含学生。
- 除主搜索框外，检查基础信息、期望/经历、更多筛选、生效标签、最近活跃时间，以及结果区排序和过滤。打开相应面板核实隐藏的已选项，不能只读搜索框。
- 用户未要求的学历、年龄、活跃时间等可选条件不主动增加，也不逐项追问。历史条件按主流程清理；平台固定默认限制无法清除时记录并说明，若与用户明确要求冲突则停止，不宣称无限制。
- 排序影响查看顺序，过滤影响候选人范围。读取实际状态；按用户要求调整。“我已看／我已聊”等不能只凭名称推断为包含或排除，先核实控件说明及选中状态，不擅自勾选。页面过滤不能替代逐人去重。

## 设置与读回

1. 先核对关联岗位，再填写关键词和城市，然后逐项设置其他条件。每次会影响其他字段的操作之后，重新检查完整清单。
2. 多关键词保留用户提供的文本与逻辑关系。录制搜索框中出现过小写 `or`，但这不独立证明平台如何解析；结合当次页面帮助或可见反馈核实。不能把搜索命中当作候选人满足专业经验的证据，也不自动扩词或使用“猜你想找”。
3. 工作年限读取当次实际选项。快捷范围无法准确表达用户要求时，检查是否提供自定义；没有对应能力则明确说明，不悄悄放宽或缩窄。
4. 用户明确要求年龄范围时，打开“年龄”→“自定义”，填写“最低”和“最高”，核对两端值后点击“确定”。随后读取控件显示及生效标签；只看输入框内容不足以认定生效。数值来自本轮要求，录制数值不是默认值。不根据照片或姓名推测年龄。
5. 学历打开“学历要求”后，读取真实选项及选择方式，区分单一学历与“及以上”。完成选择后从控件或标签确认。录制只明确捕获打开学历控件，未明确捕获最终选择，不能据此固定学历。
6. 居住地、活跃时间及其他高级条件用对应页面控件填写并读回。现有搜索脚本不支持的字段，改用页面操作；控件无法使用或不能核实时报告具体缺项，不忽略。
7. 清除条件后同样读回；如果使用“清空筛选”，重新核对岗位、关键词、地点和所有本轮保留项，避免误清。关闭遮挡结果的筛选弹层。

## 确认本轮结果已加载

条件标签更新与结果卡片刷新可能不同步。录制中出现年限标签变化而结果仍显示不一致卡片的过渡状态，因此须分开验证。

- 改条件前记录当前结果摘要，例如页面结果数量、当前页码和少量卡片稳定标识，用于识别刷新；不保存整份简历。
- 按页面实际行为触发搜索：需要“搜索”按钮时点击；条件选择后已自动刷新时，先核对完成状态，无须反复提交。
- 等待加载提示消失，重新读取条件、结果数量、页码及可见卡片；再读取一次，确认页面未继续加载且结果稳定。结果摘要变化、明确的加载到完成过程或本轮完成提示可作为刷新依据。数量不变不代表未刷新；只有等待了固定秒数、标签变化或脚本返回 `search_submitted` 均不够。
- 无法观察到本轮刷新依据时，可明确提交一次搜索再核对；最多再核对一次。工具等待超时或仍无法确认时停止，报告“条件已填写／搜索已提交，结果刷新待确认”，不循环点击，也不开始Hi。
- 若稳定结果仍明显违背已选范围，重新打开控件核查选项含义和生效值。不要直接认定是旧结果，也不要把不符的卡片认定合格；疑点无法解决时报告搜索结果异常。
- 零结果也须确认加载完成和条件准确。报告零结果，不自动扩大城市、工作年限或其他要求。

## 搜索完成后的交接

报告实际生效条件和页面原样显示的数量，区分结果总量与实际查看人数。只有刷新核实后才进入用户已要求的逐人筛选步骤；用户只要求搜索时到此结束，不进入人才管理、不标记状态、不联系候选人。
