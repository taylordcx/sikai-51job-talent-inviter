# 浏览器搜索与Hi操作

## 可见操作与平台限制

这些规则用于减少重复访问和误操作，不是“不封号”保证，也不是绕过平台检测的措施。前程无忧企业端[服务声明](https://ehire.51job.com/HTML/Agreement_c.htm?y=2018)限制使用爬虫等网络工具抓取简历信息；可见浏览器操作、只读卡片、较少Hi次数或随机等待均不代表获得平台许可。用户问及风险时如实说明，并建议向客户经理核实这种辅助方式是否允许，不声称有已验证的安全频率。

- 沿用用户已登录的可见浏览器，登录、验证码由用户完成。单窗口、单任务顺序操作，不同时启动多个岗位或页面的操作程序。
- 只通过真实页面控件搜索、滚动、翻页、发起Hi；只读取当前已显示卡片所需信息，不后台预取其他页、不直接调用候选人数据接口、不批量导出简历。
- 一次操作后等待加载结束、目标可见且没有遮挡，再读取当前页、分析、操作下一步。等待以页面状态为依据，不用随机停顿或人为鼠标轨迹伪装人工；不为完成500人目标快速连续翻页。当前页处理完才进入下一页，翻页后核对页码或结果标识确实变化，未变化时停止并记录，避免重复循环。
- 已读取的卡片资料保留最少必要的简短分析，避免重复整页读取；Hi前仍须重新核对对应卡片、条件和按钮。只点一次，核实结果后再处理下一人，绝不并行发送或自动补发。
- 默认500人是整轮查看上限，不是必须完成的工作量；确认成功发起3次Hi即停止。平台限制、额度不足及结果不明始终优先于人数目标，不能为凑数放宽标准。
- 出现验证码、频繁操作／访问异常提示、账号限制、禁止自动操作提示或明确限流响应时，立即停止浏览、翻页和Hi，保存进度并报告页面原文。不要把这些提示当作普通加载，不反复刷新、轮询或定时自动重试；用户处理后明确要求继续时，先只读检查状态、待确认Hi及本轮计数，再决定是否恢复。限制仍在则继续停止。
- 不启用旧的 `anti_detect.py`，不伪装浏览器指纹，不轮换IP、代理、账号或清除Cookie规避限制，不绕过验证码，也不更换接口或点击方式绕过失败。

## 连接和搜索

### 云端沙箱里自建 Xvfb/noVNC 是错误路线（2026-09-29 实例）

**触发条件很具体：把这个技能放进 WorkBuddy 的「项目」（团队项目）里跑，命令就落在云端了。** 判定证据是技能自己的加载路径——同一份技能，本地工作区会话读的是 `~/.workbuddy/skills/sikai-51job-talent-inviter`，项目会话读的是 `/root/.codebuddy/skills/<uuid>`；后者在 Linux 上、家目录 `/root`、有 `apt-get`，完全看不到顾问 Mac 的文件系统。所以「项目里跑」= `CLOUD_SANDBOX`，第 0 步闸门必然判停。要用本技能，就在**本地工作区会话**里发起，不要放进项目。

一次实际运行记录：技能被放进项目后在**云端沙箱会话**里重跑（命令以 root 执行、家目录 `/root`、有 `apt-get`，工作目录 `/root/.51job-talent-inviter`）。该会话因为找不到可用的平台浏览器工具，自己走成了下面这条：

```
pkill -9 chromium
apt-get install -y xvfb x11vnc novnc websockify
Xvfb :99 -screen 0 1600x1200 ; chromium --display=:99 … ; x11vnc ; websockify 6080
present_files → http://localhost:6080/vnc.html?autoconnect=1&resize=scale
```

然后向顾问汇报了一张「Xvfb ✅ 运行中、Chromium 可见模式 ✅、CDP 9222 ✅、x11vnc + noVNC 面板 ✅ 已在预览窗口打开」的全绿表格，并请顾问「在预览面板里完成登录」。**这是错误路线，四个绿灯也不是有效证据**：

- 浏览器跑在云端沙箱里，不是顾问电脑上的窗口。顾问本机既没有 `Xvfb`/`x11vnc`/`websockify`（macOS 默认都没有），也没有 6080/5900 在监听；沙箱里的 `localhost:6080` 只是沙箱自己的回环地址。
- 预览面板拿不到沙箱内的 noVNC 时，顾问看到的就是空白或连接失败——这正是「环境已全部就绪」却仍然用不了的原因。
- 就算面板能连上，登录态也只存在于沙箱内：扫码/短信验证要在沙箱的 Chromium 里重做一遍，沙箱回收后登录态即丢失，和「顾问本机 Chrome 登录一次长期复用」完全是两回事。
- 51job 企业端本身要求顾问亲自完成登录与验证码；把登录搬到云端沙箱，既不满足技能的可见性要求，也让顾问无法核对操作。

正确做法：先跑 `scripts/env_check.sh`。看到 `VERDICT=CLOUD_SANDBOX` 就停下，如实说明环境限制，请顾问到**本地工作区会话**重跑。环境判定脚本判定为云端时不得安装显示组件、不得新建虚拟显示、不得后台拉 Chromium；也不能因为沙箱里 9222/6080 探测失败就断言「产品不支持浏览器」，只能说「本轮会话所在环境做不到」。

### 第一选择：平台浏览器工具

先检查本会话实际提供的浏览器工具；若平台有工具搜索／发现功能，搜索浏览器、标签页、打开网页等能力并读取工具文档。沿用已连接的招聘页面；只有网址、没有标签页时，通过工具打开该网址，不要求浏览器预先存在。使用工具返回的页面或标签标识继续读取、点击、核对，全程保持同一浏览器上下文。不要臆造WorkBuddy专用工具名称或未提供的接口。

“可见”包括平台提供的可交互浏览器面板／远程桌面窗口，不限定必须是操作系统新弹出的Chrome。平台浏览器可能由独立服务承载，终端是Linux沙箱并不能说明该工具不可用。必须确认平台向顾问展示了可操作页面，不能仅把截图文件发给顾问就声称窗口已显示；工具文档或返回信息无法确认展示能力时说明缺项。

平台浏览器可用时，不运行start-browser、不扫描9222端口、不要求安装本地桥接或关闭沙箱。平台工具连接失败时按实际错误说明，不偷偷换成本地或另一云端浏览器。已经展示页面后再等待顾问完成登录，读取实际岗位；不能把打开链接等同于已登录。

### WorkBuddy的agent-browser入口

用户提供的运行记录显示WorkBuddy曾使用agent-browser，首次未启用headed导致用户看不到窗口，后续报告加上headed后打开登录页。这是入口排查证据，不代表已验证登录后读取岗位或Hi发送。工具可由CLI提供，没有browser／playwright MCP并不等于没有可操作浏览器。

#### macOS 上 `--headed` 仍可能看不见窗口的坑

`agent-browser` 自带的 Chrome 位于 `~/.agent-browser/browsers/chrome-*/Google Chrome for Testing.app`，是给自动化测试用的 dev 版二进制。**即便显式加 `--headed` 或设置 `AGENT_BROWSER_HEADED=1`，macOS 也可能不把它当作正常 GUI 应用注册到 Dock 或 System Events 可视进程列表**——进程确实在跑、能截图、能接受 CDP 指令，但用户在屏幕上始终看不到窗口，`osascript -e 'tell application "System Events" to get ...' ` 会因权限违例失败。出现这种情况时，按本节"用真 Chrome + CDP 接管"修法处理，不要继续断言"headed 已生效"。

修法：绕开 Chrome for Testing，直接拉起一份独立的真 Google Chrome，开 9222 远程调试端口，再用 `agent-browser connect` 接过去接管。

```sh
# 必须独立目录，避免和用户日常在用的真 Chrome 抢配置；同时让登录态持久化
mkdir -p "$HOME/.agent-browser/profile-real"

# --no-sandbox / --disable-dev-shm-usage：在受限 shell / 容器 / 沙箱里 Chrome 自带 sandbox 初始化会失败
# 不加的话 GPU 与网络子进程会反复崩溃，Chrome 启动后立刻自退
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --remote-debugging-port=9222 --remote-debugging-address=127.0.0.1 \
  --user-data-dir="$HOME/.agent-browser/profile-real" \
  --no-first-run --no-default-browser-check \
  --no-sandbox --disable-dev-shm-usage \
  "https://ehire.51job.com/Revision/talent/search"

# 用 run_in_background=true 或 nohup 启动；shell 一退出 Chrome 也会被 SIGHUP 一起带走
```

之后：

```sh
agent-browser connect http://127.0.0.1:9222
agent-browser open "<url>"     # 之后所有命令都走这个连接的会话
```

判断连上没：`curl -s http://127.0.0.1:9222/json/version` 应返回真实 Chrome 版本的 JSON。判断窗口真可见：`pgrep -l "Google Chrome"` 应能列出一组 Helper 进程；macOS Dock 应出现 Google Chrome 图标，且窗口实际绘制（`agent-browser screenshot` 返回的 PNG 与窗口内容一致只是必要条件，不是充分条件）。仍不可见时检查 System Settings → Privacy & Security → Accessibility / Screen Recording 是否放行了当前 shell 或终端。

#### agent-browser 连接后仍可能操作到"另一个浏览器"（2026-09-29 实测）

`agent-browser connect 9222` 显示成功后，它管理的标签页可能不是真 Chrome 里已登录的那个：agent-browser 会在隔离的 browser context 里新建标签，**不共享默认 context 的 Cookie**，表现为 `get url` 返回 `about:blank`、`tab list` 只见一个空白页、导航到 ehire 后被踢到登录页——而 `curl http://127.0.0.1:9222/json` 里明明能看到已登录的"人才搜索"标签。此时不要让用户重新登录，改用**原生 CDP 直连**驱动原标签：Node 22+ 自带 WebSocket，写小脚本 `fetch('/json')` 找到 ehire 标签的 `webSocketDebuggerUrl`，用 `Runtime.evaluate`（设 `awaitPromise:true` 支持页内 async）读 DOM、改筛选；用 `Input.dispatchMouseEvent`（mousePressed+mouseReleased）发真实点击。坑：
- 页面是 Vue SPA，合成 `element.click()` 对部分控件无效，**真实鼠标事件（Input.dispatchMouseEvent）才可靠**；点击前先 `getBoundingClientRect` 取中心坐标。
- **僵尸 `el-loading-mask`**：搜索重渲染后可能残留透明遮罩（opacity 0 但仍拦截指针），`elementFromPoint` 命中 `.el-loading-mask` 即中招；把它 remove 或 `pointer-events:none` 后点击才有效。
- **残留弹层盖住弹窗**：基础信息行的筛选下拉（.el-popover.base-select-popper）可能悬停不关，盖住后开的居住地/城市弹窗导致点击落空；`elementFromPoint` 验证落点，必要时 `display:none` 隐藏残留弹层。
- 居住地/期望工作地弹窗是**三列级联**：列1省份、列2城市、列3"全省"leaf 项；点列1只展开不选中，必须再点列3的同名 leaf 才算选全省，以"已选(n/10)"计数和确定后"当前居住:…"标签为准。选项上限 10 个，16 省默认范围按 10+6 两批。
- 年龄/年限的"自定义"输入是弹层内两个输入框（最低/最高），填完点弹层内"确定"；用 `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set` + `input` 事件才能让 Vue 收到值。注意确认自定义值落在**正确的筛选器**弹层里（年限和年龄的弹层长得一样，先核对弹层内选项文本）。
- **结果卡片容器是 `.item.resume-card`**（不是里面更窄的包裹层，窄层会漏掉"求职意向"和证书标签）。列表是虚拟列表，一次只渲染约 30 张，滚动才加载更多。读卡片用 `document.querySelectorAll('.item.resume-card')` 定位。
- **"立即Hi聊"按钮默认 `display:none`，悬停卡片才显示**（`.el-button.tm_button`，getBoundingClientRect 返回 0×0）。`Input.dispatchMouseEvent` 的 mouseMoved 不一定能触发 CSS 悬停。可靠做法：先给按钮设内联 `style.display='inline-flex'; style.visibility='visible'; style.opacity='1'`，再 `getBoundingClientRect` 取坐标，用真实 mousePressed+mouseReleased 点击。点击处理器是 Vue 绑定的，内联改样式不影响它触发。
- **Hi 发送成功的判据（三选二以上）**：① 该卡片按钮文字变成"继续聊"；② 出现 toast"消息发送成功，可在右侧聊天小窗内查看"；③ 右上"Hi聊点数"数字下降。看到 ①③ 才算确认，仅"按钮消失"不算。
- **"精选"标记的候选人额外扣点**：Hi 后弹出"扣数规则说明"（点"我知道了"关闭），规则为每次 Hi 扣 1 点基础点数，精选人才额外扣 1-2 点。实测一位"精选"候选人使点数 3→1（扣 2 点）。邀约前先看右上点数，提前判断还能约几人。
- **给真标签取证要用 CDP `Page.captureScreenshot`**；`agent-browser screenshot` 截的是它自己隔离标签的页面（会拍成未登录的登录页），不能当作真标签的执行证据。
- **shell 传参的坑**：把较长的 JS 表达式用 shell 双引号直接传给 node 时，偶发返回 `{}`（疑似引号/转义被吃掉）。稳妥做法是把表达式写进 `.js` 文件，用文件版 eval 脚本（读文件内容再 `Runtime.evaluate`）执行，复杂表达式一律走文件。

### 已验证工具链：scripts/cdp_tools.mjs（WorkBuddy 首选）

上述 CDP 直连路线已固化为技能自带的统一工具 `scripts/cdp_tools.mjs`（2026-09-28/29 全流程实测：连接、筛选、读卡片、发 Hi 均验证通过）。环境要求：带 9222 调试端口的真 Chrome 在跑、已登录、Node 22+。用 `CDP_PORT` 环境变量可改端口。

```sh
NODE=/path/to/node          # Node 22+
TOOL=scripts/cdp_tools.mjs  # 技能目录下

# 只读
$NODE $TOOL points                    # Hi 聊点数余额
$NODE $TOOL cards 0 5                 # 读第 0-4 张卡片（.item.resume-card，含求职意向与证书）
$NODE $TOOL point 356 200             # 查视口坐标处元素（排查遮挡）——**每次点击前都先跑一次确认落点**
$NODE $TOOL shot /tmp/x.png           # 截真标签的图（取证用）

# 页内求值：短表达式用 eval；长/复杂表达式一律写 .js 文件用 eval-file（shell 引号坑）
$NODE $TOOL eval "document.title"
$NODE $TOOL eval-file expr.js

# 操作
$NODE $TOOL click 1072 367            # 真实鼠标点击（先 scrollIntoView + getBoundingClientRect 取中心坐标）
$NODE $TOOL type 373 620 "22"         # 点坐标 → focus 输入框 → 全选 → 真实输入（Vue 表单填值必用）
$NODE $TOOL fill 最低 "22"            # 同上，按 placeholder 定位
$NODE $TOOL esc                       # 发 Escape 关弹层
$NODE $TOOL provinces "湖南,河南,..."  # 居住地弹窗内逐省选"全省"（三列级联，自动处理首次点击只激活的情况）

# 发 Hi（含全部防呆：点前读余额、已沟通过自动跳过、按钮强制显示、只点一次、点后三重证据验证）
$NODE $TOOL hi 0                      # 对第 0 张卡片点"立即Hi聊"，输出证据与判定
```

`hi` 子命令的成功判据（至少两项才算"已发起Hi"）：卡片按钮变「继续聊」、toast「消息发送成功」、Hi 聊点数下降。证据不足输出「结果待确认」，**不得补点、不得换方式重发**。按钮已是「继续聊」的卡片自动跳过（防重复邀约）。

#### 复跑踩实的操作细节（2026-09-29 第二轮）

- **Chrome 必须常驻启动**：用 `nohup … &` 起的话，那条 bash 一结束 Chrome 就跟着没了（9222 先通后断）。用 `run_in_background=true` 起，或在同一条命令里起完立刻用。
- **每步都要重新取坐标**：设置完一个条件后页面会整体重排（实测筛选标签 y 从 247 → 281，`工作年限` 变成 `1-3年` 后同排标签 x 也会平移）。上一步的坐标一律作废，点击前先 `eval` 取 `getBoundingClientRect`。
- **切换岗位会重置期望工作地**：从「财税专员」改成「助理财税咨询师」后，原本已选的「义乌+杭州」退回单城「义乌」。所以地点必须按主流程放在最后设，并再次读回。
- **居住地弹窗**：标题右侧读「已选( n /10)」，上限 10，16 省按 10+6 两批。选中结果以弹窗内标签（湖北省 湖南省 …）读回，不能只看计数。**陕西与山西相邻**，首次点第三列同名 leaf 常只激活不选中（计数停在 9/10），再点一次才生效；省份标签文案变化会让后面标签的 x 平移，重试前要重取坐标。
- **期望工作地弹窗（选择城市）**：城市是**两列并排**（每行两个城市：`浙江省 / 杭州`、`温州 / 绍兴`、…、`义乌 / 海宁` 各占一行左右两格），不是三列展开；城市列表会滚动，先找到含目标城市的 `ul.cascader_panel_menu` 并 `scrollTop = 0`，再按坐标点。已选读回要看「已选 n /10 义乌 杭州」。**注意 chips 只渲染首个城市**（页面顶部条件条显示「期望工作地:义乌」），真实值要读输入框 `.value`（会显示「义乌+杭州」）。
- **结果页读回条件**：搜索后页面顶部会输出当前生效条件（`当前居住:湖北省、湖南省…｜年龄:25岁-30岁｜工作年限:1年-3年`）+ `共搜出 N 个结果`，这是"条件真的生效"的最终证据，比点击成功更可靠。

#### 复跑踩实的操作细节（2026-09-29 第三轮）

- **`type` 子命令：CDP click 不会给 input 焦点**。`cdp_tools.mjs type <x> <y> <text>` 现在的实现是：真实点击 → `document.elementFromPoint(x,y).closest('input,textarea').focus()` → 发 Cmd+A 全选 → `Input.insertText`。少了 focus 那步，`insertText` 会插到 body 上、input 仍为空（readBack 会如实返回空串）。
- **长弹层会把「确定」挤出视口**。年龄「自定义」弹层（含 7 个快捷档位 + 两个输入框 + 按钮）整体高约 470+ px，当入口在筛选栏偏上位置时，`确定` 的 y 会 > viewport 高度（实测 708），此时 `Input.dispatchMouseEvent` 点不到它。修法：先 `document.querySelector('.main_container').scrollTop = 120` 让弹层整体上移，然后**重新读一次按钮坐标**再点（滚动后坐标必变）。判断按钮是否可点：`r.y > 0 && r.y < innerHeight`。
- **弹层档位要用 TreeWalker 读文本节点**。用「叶子元素 + `innerText` 正则」过滤只读到「不限」一项（档位 DOM 有子元素/空文本节点），改用 `document.createTreeWalker(pop, NodeFilter.SHOW_TEXT)` 遍历文本节点、取 `parentElement.getBoundingClientRect()`，能一次读全 7 个档位及坐标。
- **点击前必须 `point <x> <y>` 确认落点**（本轮最大教训）。弹层关闭后，上一步记下的坐标会**击穿到下层元素**——本次就是点完弹层「确定」后，残留坐标落到了候选人卡片上，直接跳进了简历详情页（`talent/resume/detail`，违反"只看卡片不开详情"）。规则：任何点击前先跑一次 `point`，确认落点 class 属于预期控件（如 `confirm_button` / `option-item` / `cascader_panel_item`）再点。
- **误入简历详情后无法用 history 回退**。51job 的搜索页与详情页是同标签 SPA 路由替换，`Page.getNavigationHistory` 只返回 1 条（当前详情页），`history.back()` 无效。只能 `Page.navigate` 回 `https://ehire.51job.com/Revision/talent/search`，**代价是筛选条件全部重置**（岗位标签还在，年限/年龄/居住地/期望工作地全丢，关键词框也会空），需按主顺序重设。所以宁可点前多确认一次，也不要事后补救。
- **岗位下拉入口点箭头不点名称**。搜索栏结构：`[期望工作地输入框 x302-410] [岗位标签 .cur_selected_job_tag x430-540] [关键词输入框 x540-834] [搜索按钮 x836-956]`。岗位标签内 `.cur_selected_job_tag_arrow` 在 x≈518-532（下拉箭头，点它打开下拉），标签名在 x≈458-514。**点标签名附近有误触 × 删除岗位的风险**，打开下拉请点 `(525, 200)` 这个箭头位置。
- **重选岗位会带回关键词、但会重置期望工作地**。页面导航后关键词框会空（搜出 0 条、提示"没有搜到相关的人才"），此时重选一次岗位即恢复平台自动带出的搜索词（`财税专员 or 会计专员 or 税务专员 or 财务专员 or 账务处理`）；但同一次操作会把期望工作地从「义乌+杭州」退回单城「义乌」。因此固定顺序：**选岗位（带关键词）→ 设年限/年龄/居住地 → 最后设期望工作地 → 搜索**，且搜索前用 `point` 确认搜索按钮落点（class 含 `search_button`；禁用态会带 `text_disable`，仍可点）。
- **弹层「确定」点击是否生效，用"弹窗数=0 + 标签读回"双确认**：`[...document.querySelectorAll('.el-dialog')].filter(e=>e.offsetParent!==null).length` 归零，并且筛选标签文本已变成目标值（如「居住地 · 10」），二者缺一就不算完成。

### 第二选择：本地桌面脚本

仅在平台浏览器工具不可用且命令确实运行于顾问本地桌面电脑时采用以下备用路线。若两条路线都不可用，报告已检查的能力及具体失败原因；不要只根据终端环境断言整个产品不支持浏览器。

先区分执行脚本的电脑与用户桌面。云端／容器里的127.0.0.1仅指该环境，不能连接用户电脑的9222端口。优先使用平台已提供且用户可见的浏览器工具；本地启动脚本适用于有桌面的Mac、Windows或普通用户Linux会话。没有Linux显示环境或以root启动时，脚本会在启动前停止，不能通过延长等待、扫描更多端口、添加headless、--no-sandbox或新建虚拟显示来替代用户可见窗口。环境变量存在也不证明显示服务可用；未验证就绪时不得声称启动成功。说明实际运行环境和所需的本地／平台浏览器连接，不把用户电脑上的历史连接记录当成本轮连接证据。不要求用户把调试端口暴露到公网。

已有可用浏览器工具时直接使用它读取页面、选择岗位、填写条件和点击。不要仅因为自带脚本使用调试端口就要求用户换浏览器。按工具文档操作，不能混用不同浏览器的登录状态和元素标识。

自带脚本的备选方式：在技能目录执行下列命令，使用已启动的本机Chrome或Edge调试端口9222。读取不到端口不代表账号未登录。满足上述本地备用条件后，用 `start-browser` 启动或显示可见窗口，返回 `browser_ready` 仅表示页面已显示，不代表已登录。页面要求登录时等待顾问登录，再运行 `jobs`。启动需要系统权限时申请该权限，不能跳过后宣称已打开。

```sh
python3 -B scripts/consultant_search.py start-browser
python3 -B scripts/consultant_search.py jobs
python3 -B scripts/consultant_search.py template
python3 -B scripts/consultant_search.py search-browser --request request.json
```

默认只选择招聘岗位，不主动重填关键词。脚本会写入keywords且依赖明确关键词时，不把它当成本轮默认入口；先用浏览器下拉选择岗位，保留平台实际带出的搜索词并检查结果。不能为通过脚本校验而输入岗位名或复制提示词。由助手把顾问自然语言填写进请求文件，不让顾问编写JSON。`jobs`读取当次岗位选项；`job_key`从当次结果取得。多个企业端页面时通过`--target`指定正确标签页。

启动入口会优先沿用已有调试窗口；没有连接时启动Chrome或Edge，并优先使用本机已存在的旧技能浏览器目录以保留登录。已有招聘窗口但未连接时先说明情况，不悄悄切换。需要另行启动调试浏览器时，使用可见窗口、本机地址127.0.0.1、端口9222和独立用户目录`~/.51job-talent-inviter/browser-profile`，打开`https://ehire.51job.com/Revision/talent/search`。遵守执行环境的启动权限要求，让用户在该窗口完成必要登录。不关闭用户原有浏览器、不复制Cookie、不降低浏览器安全设置。

自带脚本只适配关联岗位、关键词、期望工作地、工作年限快捷选项及学历快捷选项。当前居住地与期望工作地不能互换。默认居住范围按[16个省级地区](default-residence.md)执行，需要浏览器工具实际填写与核对；不能仅靠搜索脚本完成本技能。高级条件用实际浏览器控件补充并读回，不能传给尚未支持它的脚本后假装成功。多关键词的OR语法须当场核实；不自行拼接职位后缀。

## 每位候选人的操作顺序

1. 只从当前结果卡片取得候选人标识和对应职位，读取筛选所需资料，不打开详情。可读取卡片上已有简历链接的地址（不点击）或平台候选人编号识别，同名不视为同一人。候选人身份不能可靠区分时跳过。
2. 检查本地记录和页面是否已沟通。以企业账号和候选人稳定标识去重，不能仅按姓名或卡片序号。已有成功、正在处理或结果待确认的记录均不重复点击。
3. 按[卡片匹配分析](card-analysis.md)先完成分析，对本轮每条必须条件逐一记录证据。结论为“推荐邀约”且满足全部必须条件才能行动；“待核实”或“不匹配”跳过，不打开详情补全。岗位地点、搜索筛选标签不能当作候选人自身的证据；“3年工作经验”不能证明“3年某专业经验”。
4. 点击前重新读取该候选人卡片，核对身份、条件和Hi按钮归属；检查页面可用额度，明确为0时停止。可用点数少于顾问上限不算故障，先按现有点数执行，例如上限10人而只有3点，最多尝试3人，每次后重新读数。额度未知时不推测可用次数；出现额度不足立即停止，不充值、不购买权益。
5. 在本地记录中先标记该候选人为“正在处理”，再通过真实浏览器点击其卡片内部唯一的Hi／立即Hi聊按钮一次。不要全页批量选择Hi，不复用滚动或翻页前的坐标，不并行点击多位候选人。用 `cdp_tools.mjs hi <cardIndex>` 执行时，防重复（已是"继续聊"自动跳过）、按钮强制显示、只点一次、点后验证已内建；手动执行时参照"已验证工具链"小节的强制显示方法。
6. 若平台弹出本次Hi的岗位选择或普通确认框，核对仍是本轮岗位、候选人和邀约含义后继续完成。涉及付费购买、交换或下载简历、电话外呼等不同动作时停止，不把它们当作普通Hi确认。
7. 等待页面响应，核实属于该候选人的新状态，例如刚出现的成功提示、已沟通状态或本次已发送的会话记录。仅打开空白聊天窗口不算已发送；仅按钮消失或点击调用返回也不算成功。
8. 成功记“已发起Hi”；明确失败记失败原因；超时、遮挡、断线或证据不足记“结果待确认”，停止继续发送并只读检查。**不得因为没有看到提示再点一次Hi**，也不得改用另一种点击方式补发。确认前保留记录，不能删除后重试。

## 执行记录

由助手在当前工作区保存专用记录文件，每次动作前后更新，后续运行读取同一记录路径。若工作区变更，应沿用已知记录位置或先核对历史，不将新文件误认为从未联系过。

最小字段：账号标识、候选人稳定标识、本轮岗位、条件及核对证据、时间、状态、结果依据。状态包括：不符合、信息不足、正在处理、已发起Hi、明确失败、结果待确认。只保存本次判断和去重所需资料，不保存整份简历或Cookie。

## 测试边界

创建或维护本技能时可用模拟页面验证流程；不得把真实候选人当测试对象。本轮没有实际岗位和筛选条件时，完成技能创建即可，不能拿参考截图的值发起邀约。上线后首次实际使用仍须读取当时真实页面，不能把搜索脚本测试通过宣称为真实Hi已经验收。

## 加载与遮挡恢复

加载遮罩和实际弹窗分别处理。暂时加载时最多等待15秒并只读检查；加载消失后继续，不让顾问反复重试。岗位下拉自身加载时先收起，再核对主页面。真实弹窗、验证码或持续加载不能直接忽略；记录具体原因。等待可以重试读取，Hi发送绝不自动重试。筛选点击后等到实际选中值更新，再操作下一字段。城市搜索建议有时挂在弹窗外，应读取唯一可见且名称精确匹配的选项，再核对已选标签。

## 顾问输入年龄

每次收集年龄上下限或明确的“不限”。按页面实际控件打开年龄→自定义，填写顾问给出的最低、最高年龄，确认后核对生效标签的两端值，不能用附近快捷范围代替。只对本次任务使用具体数字；不把演示值或当前任务值写成永久默认。年龄条件目前由浏览器操作，不向不支持该字段的搜索脚本传入伪造字段。
